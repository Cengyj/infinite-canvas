# 当前修改复查与验收说明

本轮已确认并修复请求参数、跨域诊断、项目隔离、媒体清理和 Agent 生命周期中的实际问题。版本号仍为 `v0.19.0`，未发版本、未发布 npm 包。

复查时使用的是不含 `.git` 的本地源码目录，以现有源码、`CHANGELOG.md` 的 `Unreleased` 和行为测试为依据；上传时已接续目标仓库的 `main` 提交历史。静态审查和模拟行为测试不等同于真实模型接口验收。

## 当前项目结构

| 部分 | 职责与数据边界 |
| --- | --- |
| `web/` | Vite + React + TypeScript；Zustand 管理配置、素材、画布及 Agent 状态；项目、媒体和生成历史主要通过 localforage 存在浏览器 |
| `web/src/services/api/` | 模型、提示词、Agent 等请求；AI Key 由当前网页持有，模型服务默认前端直连，可经本地代理 |
| `canvas-proxy/` | 独立 Node 转发工具；默认监听回环地址，接受任意合法 HTTP(S) 页面来源，不保存业务数据 |
| `canvas-agent/` | 独立本机 Agent/MCP 服务；Token 鉴权、会话事件与本地消息元数据，不是 AI 模型业务后端 |
| `web/src/services/app-sync.ts` | 可选 WebDAV 同步，画布、素材、图片历史、视频历史分别合并与上传 |
| `plugins/`、`docs/` | 插件入口、使用文档和人工验收清单 |

## 确认的问题与处理

| 优先级 | 触发方式与原问题 | 本轮处理 |
| --- | --- | --- |
| 高 | 在上传、裁剪、截帧或生成未完成时切换画布，旧组件闭包仍可修改新项目 | 按项目 ID 挂载独立画布实例，卸载取消生成请求 |
| 高 | WebDAV 同步触发全局清理，撤销历史或工作台临时参考只在页面内存中，文件可能误删 | 统一登记页面实时引用，清理识别撤销、剪贴板、临时参考与生成结果 |
| 高 | 生成来源存为 `metadata.references` 字符串，原清理只识别对象 `storageKey` | 两种媒体扫描均识别字符串存储键，保留重试所需来源 |
| 高 | 清理读取旧快照期间新文件写完，或排队删除期间图片被重新引用 | 记录写入修订和活跃写入；实际删除前再次检查引用，并在确定删除后释放 URL |
| 中 | Agent 生图时平移、缩放或选中节点，快照 effect 清空 context 造成假的项目切换 | 快照直接更新，仅实际项目变化或卸载时清理所属 context |
| 中 | Agent 失败事件仍尝试导入；异步读取图片期间切线程，旧活动可能写入新线程 | 对齐服务端成功状态条件，读取完成后复核连接与线程 |
| 中 | 代理对完整 URL 额外 `decodeURI`，改变 `%252F`、`%41` 等编码 | 保持原路径和查询编码，端到端验证上游收到原值 |
| 中 | Gemini 流式请求在已有查询参数后再追加 `?alt=sse` | 在套代理之前通过 URL 查询参数设置 `alt=sse`，保留其他参数 |
| 中 | 旧扁平配置恢复时混入默认视频/音频模型 | 渠道恢复仅使用旧配置实际保存的模型字段；新安装仍保留完整默认渠道 |
| 中 | Veo 内置模板将 HTTP 错误、取消和代理故障回退成成功 URL，并移除 CDN token | 仅允许直连跨源网络失败回退，保留 CDN 签名；认证下载失败正常报错 |
| 中 | 直连服务的 `origin not allowed` 被说成本地代理拒绝，代理测试对任何 403 都误报 | 来源拒绝按实际请求地址、403 和诊断证据判断；检测代理身份与响应状态 |
| 中 | 代理连通性或版本检查遇到无响应时一直等待 | 增加覆盖响应正文的 5 秒和 15 秒超时，手动版本检查显示代理诊断 |
| 高 | WebDAV 未校验清单版本，缺少主要数据结构也当空内容继续同步 | 未知版本或缺少主要结构时拒绝覆盖该数据域；其他合法域仍可能正常同步 |

## 定制功能保护

- Google 生图保留 `inlineData.{mimeType,data}`、`responseModalities`、`generationConfig.imageConfig`、模型尺寸能力校验，以及 `2880x2880` 对应 4K 的识别。
- 保留既有脚本的 `params.size` 语义与补充的 `requestedSize`；自定义渠道、Key、模型选择和用户主动删除项不被默认配置覆盖。
- 自定义脚本仍优先于内置模型请求，保存的脚本不被自动重写。模板修复只影响新插入模板；希望采用新版逻辑的已有脚本需主动更新。
- 自定义 `fetch(Request, init)` 的方法、正文、请求头覆盖、取消信号和签名查询参数均有行为测试。
- GPT Image 继续使用对应输出格式/背景参数，其他模型保留 `response_format` 分流；Veo 同渠道下载继续通过 Header 认证，跨域公开 CDN 不附带渠道 Key。
- 局部遮罩编辑使用两张普通参考图是当前已记录的功能方案；请求中移除 `mask` 字段属于该方案，不是本轮误覆盖。

## 跨域结论

网站部署在自己的域名、API 填写另一个域名是现有正常直连场景。项目不要求二者同域，不因域名不同自动打开代理。代理工具和开关来自上游 v0.18，本次版本合并保留该可选功能。

本地代理继续默认接受任意合法 HTTP(S) 页面来源，不自动附加单一 Origin 限制。浏览器自身的 CORS 策略无法由网页代码关闭；源服务不支持跨域读取时，通过本机代理转发解决。

`Origin: null`、非法 Origin 的诊断、Agent Token 鉴权、Gemini operation 同源检查各自保留。其中 operation 检查用于避免向其他服务器发送渠道凭据，不应作为普通跨域限制移除。

`canvas-proxy` 源码包版本为 `0.1.1`。本轮没有发布包，`npx @basketikun/canvas-proxy@latest` 不保证包含本地修复。可以在仓库运行 `node canvas-proxy/index.js` 使用本地源码。Canvas Agent 的源码和已有 `dist/` 可能不同，本轮未构建，测试本地 Agent 源码可在其目录使用 `npm run dev`。

## 异域 API 请求专项复查

| 请求阶段 | 已核对的代码行为 |
| --- | --- |
| 渠道地址保存与导入 | HTTP(S) 地址校验不比较网站域名；地址匹配仅规范化路径，查询参数参与渠道区分 |
| 模型 API 拼接 | `buildApiUrl` / Gemini URL 函数沿用配置的 API 域名，拼接模型路径与参数 |
| 直连或代理选择 | `withLocalProxy` 只依据显式代理开关选择；关闭时不改成网站域名，也不强制转发 |
| 视频异步轮询及下载 | 相对地址以 API 提供方解析；operation 的同源校验针对提供方，用于保护渠道 Key |
| 错误展示 | 域名不同不是报错条件；无法判断原因的网络错误保持中性，代理拒绝只认专用响应标记 |

专项检查确认并修复以下问题：

1. 渠道导入对完整 URL 去末尾 `/` 或 `/v1`，会修改 `?tenant=team/`、混淆 `?route=/v1` 与 `?route=`。现在只处理 `pathname`，避免错误合并与凭据覆盖。
2. 原生 Veo 的协议相对 operation 校验时使用提供方 HTTPS，但发送时跟随网页 HTTP。现在先解析为绝对地址，再校验、清理旧查询 Key 并发送。
3. Veo 内置模板直接返回相对视频地址，后续会按网站域名下载。现在按 API 提供方解析后下载；用户保存的脚本不自动改写。
4. 上游 403 正文中的 `origin not allowed` 在经过代理时仍被当作代理来源拒绝。现在只识别代理专用标记，同时移除为了猜测错误而克隆、完整读取响应正文的路径。
5. 代理已将分块上传收集成 Buffer，却仍转发 `Transfer-Encoding: chunked`，导致 Node 拒绝请求并返回 502。现在过滤该传输头，业务正文及认证头不变。

同时调整设置页中英文说明，明确网站和 API 可以使用不同域名，代理是按需开启的工具。默认开关、模型提交字段、已有渠道和保存的调用脚本均保持原有语义。
