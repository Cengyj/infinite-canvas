# Grok 视频请求与前端约束方案

本轮稳定性优化保持原 UI、模型协议和已确认的 Grok 参数边界，集中处理素材导入归属、异步任务失效与取消，并沿用现有分层整理请求校验及组装。此前渠道样本和单图 1080p 回归属于历史证据，本轮不新增付费生成；完整浏览器流程与模型质量仍需验收。

## 范围与架构

严格审查清理：删除请求层五份重复参数转换和页面纯转发函数、未使用常量，设置组件直接读取全局配置动作；导入只识别模型及共用 7 图常量，不再解析无关生成参数。Agent 复用校验结果，统一不支持参数列表，并修正旧五字段工具说明；简化优化上下文的重复分支。保留原 UI、协议、边界及必要的取消、队列和文件归属注释。

只识别 `grok-imagine-video`、`grok-imagine-video-1.5` 两个精确名称，同时要求模型能力为 `video`、所属渠道为 `openai`、没有保存的自定义调用脚本。工作台使用实际 `videoModel`，画布使用节点配置与实际选材。未知别名、Gemini 协议和保存脚本不套用内置 Grok 规则。

- 入口负责快照与回填，画布保留组展开、token 选材和去重。页面私有 `pages/video/use-video-references.ts` 的 factory 只管理异步导入会话，hook 管理 React 状态与反馈，不新增全局导入状态。
- `lib/video-generation-config.ts` 纯函数解析实际参数及问题，不写 store、不读媒体、不偷偷改值。公共断言返回已校验的解析结果，创建请求复用该结果，不重复解析。
- `services/api/video.ts` 在同文件拆分 Grok JSON 与通用 multipart 请求体组装，共用 POST；其他 OpenAI 请求字段、Gemini 协议和保存脚本优先级不变。
- 复用任务 ID/provider、查询、下载、本地存储、鉴权及直连/代理；公共取消统一为 AbortError，查询结果返回后复查取消，并清理等待监听器。不新增任务系统、超时、重试或并发设置。
- 优化服务、hook 和弹窗沿用现有分层，只同步实际生成语义和快照，不替换会话保护。

## 请求合同与渠道证据

此前渠道调研从 yuanai.uk 的 `/api/status` 文档入口定位到[渠道 Grok 接口说明](https://qingfeng.apifox.cn/497886448e0.md)。当时文档与已完成请求一致，使用 `POST /v1/videos`、Bearer 鉴权及以下六字段 JSON。本轮保留该合同，未重新开展渠道调研；下例仅为结构示意，不含真实素材：

```json
{
  "model": "grok-imagine-video-1.5",
  "prompt": "让图片中的小猫自然地向前奔跑",
  "seconds": "6",
  "aspect_ratio": "16:9",
  "resolution": "720p",
  "reference_images": [{"url": "data:image/png;base64,<完整图片内容>"}]
}
```

- `seconds` 仍为字符串；`resolution` 使用 `480p/720p/1080p` 形式；`reference_images` 按实际选材顺序发送，每张原图只出现一次完整 data URL 对象。
- 原界面的尺寸与比例用于推导 `aspect_ratio`，分辨率映射为 `resolution`。不再发送 `size` 或 `images`；无图使用空参考数组，已采样的无图任务均完成。
- 不发送 `mode`、`first_frame`、`last_frame`、`image[]`、`resolution_name`、`generate_audio`、`watermark`。1–7 图均为普通参考，不从两张图推断首尾帧，此前采样没有测试首帧模式。
- 旧模式、声音、水印值仍可供其他模型使用，不迁移或清空；内置 Grok 不把它们当有效控制。其他 OpenAI multipart、Gemini、用户保存脚本和原任务处理不变。
- 该合同来自此前 yuanai.uk 实测，不等同于 xAI 原生接口或所有转发渠道。此前四例真实项目服务调用验证了创建与查询；完整浏览器流程及其他渠道仍需单独验收。

以下为此前采样记录，本轮稳定性改动没有新增付费生成。补充额度后共 27 次创建尝试：23 次隔离 HTTP 请求与 4 次真实项目服务调用，16 个任务 completed 且全部下载核对元数据，11 次明确参数拒绝，没有余额拒绝。累计两轮 40 次创建，21 个成片、14 次协议/参数拒绝、5 次历史余额 HTTP 403；历史余额失败不作为能力拒绝。所有参考图均采用普通 reference_images 语义，按范围没有测试首帧模式。

此前两轮全部 21 个成片均已下载核对元数据。首轮五个成片还在独立浏览器页面核对：均 readyState=4、无媒体错误、时长约 6.041667 秒。后续用 Hachoir 核对，其中四个真实项目服务的 1 秒任务，以及 1.5 无图/单图的 1 秒 1080p 样本均约 1.042 秒。样本尺寸为 480p 档 848x480、720p 档 1280x720、1080p 档 1920x1088。少数已完成任务下载时曾出现 HTTP/TLS 异常，手动重读已有 URL 后成功，没有重新提交生成，也没有调整生产重试策略。

此前实测属于关键边界采样，不是清晰度×每个图片数×每个秒数的穷举，也不是画面质量通过。中间组合、完整浏览器入口、取消与恢复交互仍需单独验收。样本尺寸不能写成逐像素输出保证。

## 当前本地策略

用户已确认“按实测放开”：1.5 在实际普通参考图为 0–1 张时支持 1080p，2–7 张仍仅支持 480/720p。共享 resolver 与 Agent 条件描述保持一致。经典型号、7 图总上限、时长规则和默认 6 秒/720p/1:1 均不变；示例的 16:9 不改变默认值。

| 型号 | 实际图片数 | 输入语义 | 时长 | 分辨率 |
| --- | --- | --- | --- | --- |
| `grok-imagine-video` | 0 | 文生视频 | 1–15 秒 | 480/720p |
| `grok-imagine-video` | 1–7 | 普通图片参考 | 1–10 秒 | 480/720p |
| `grok-imagine-video-1.5` | 0 | 文生视频 | 1–15 秒 | 480/720/1080p |
| `grok-imagine-video-1.5` | 1 | 普通图片参考 | 1–15 秒 | 480/720/1080p |
| `grok-imagine-video-1.5` | 2–7 | 普通图片参考 | 1–15 秒 | 480/720p |

固定比例继续为 `1:1`、`3:4`、`4:3`、`16:9`、`9:16`、`21:9`，接受对应分辨率计算结果相符的像素尺寸；`auto` 和任意自定义宽高不适用。上传视频/音频参考仍拒绝，不静默删除连线或附件。基础检查拒绝空来源、非 image data URL、非 base64 格式和空内容，不宣称完整图像解码；原图读取沿用 signal，组装后已取消则不得 POST。无效输入保留原值，提交前提示，不裁图、不自动换模式、不降清晰度、不缩短时长。

保持最多 120 次查询、pending 后间隔 2.5 秒，不新增超时、重试、文件大小或并发限制。查询次数不是严格的总耗时上限；取消修复保护现有请求和结果提交边界，不改变任务恢复语义。

## 界面、素材与 Agent

响应校验沿用公共请求层。failed/cancelled 优先于残留结果 URL；HTTP 错误及声明为 JSON 的正文（含损坏正文）均不得成为成功视频，本地保存失败必须向外反馈，仅网络/CORS 下载失败保留 URL 回退。取消仍为 AbortError；原模型/渠道校验、同渠道换密钥和脚本缓存恢复保留。

画布按路由 ID 隔离实例，layout 清理使控制器失效，恢复/预检迟到不得在离页后注册新请求。控制器 Map 是唯一任务登记，移除重复轮询 Set；停止后可立即重试，旧请求收尾不能清除新归属。

保留四列分辨率布局、W/H 输入、auto、时长滑块和“首尾帧／全能参考”两个控件。不支持选项仍可见但禁用：1.5 的 0–1 图可选 1080p，2–7 图禁用该档。先选 1080p 再加入第二张图时保留素材和原设置，提交前报告 resolution 问题，不裁图、不自动降级。Grok 两个模式按钮仍禁用且没有有效选中态，摘要不显示旧模式。不新增解释区域、计数或常驻错误列表；其他模型及脚本继续使用原控件。

内置 Grok 导入将已有与待导入图片共同计入 7 图上限，超限整批拒绝、按调用顺序提交。剪贴板读取前捕获会话；Grok 模型切换往返或脚本变化即时使旧会话失效。重置/卸载中断上传，并释放等待旧剪贴板的提交闸门。Promise.allSettled 后只清理未归属临时 key；迟到结果、错误及清理期间失效的反馈不得进入当前会话。Grok 导入中生成仍提示等待。

非 Grok 导入继续按剩余容量裁取，保留满 7 图时素材库关闭、有效会话新增 0 图成功反馈及剪贴板读取错误提示。空参考说明现在读取既有 7 图常量，仅纠正原 9 图文案，实际限制及布局不变。

画布继续按真实选材展开、token 与去重结果校验。存储完成后，在一次同步发布中检查归属、提交节点并确认接收，再以 claimStoredMedia 交接新文件；renderer 接收后即使抛错也不删除已归属文件。节点缺失、替换或取消只清理未发布的新 key。共享 GC 纳入视频日志及实时素材/项目/草稿引用，保护在途写入，扫描期间归属变化则保守退出；恢复/读取失败不被视为空集合。此进程内保护不等于跨标签事务保证。

Agent 查询返回六字段合同及 `referenceCountsKnown: false`，不猜测工作台素材数量。经典仍为无图/有图两段；1.5 明确列出 0、1、2–7 图三段及对应清晰度范围。不把 `mode`、`generateAudio`、`watermark` 宣传为 Grok 有效控制；显式提交这些字段时，在任何配置写入前拒绝，不返回“成功但忽略”的 applied。通用工具 schema 保留这些字段供其他模型使用，实际生成仍按真实素材数量校验。

页面私有 video-generation-tasks 协调器区分挂载视图与日志所属任务，按日志串行保存/删除；只采纳最新读取，普通刷新不重复恢复。离页中断查询但保留迟到创建 ID，在途存储只完成一次。删除使旧回调失效，失败删除恢复原记录。连续写失败保留本会话权威失败记录，恢复后重试原任务，不重复创建；终态与参数取当前记录，不能被旧回调绕过。共享 GC 计入当前草稿，成功日志持久化后显式交接媒体。Agent 唯一任务 ID 与命令序号分离，删除 pending 记录只报告停止跟踪，不声称取消远端任务。

## 提示词优化

所选文本模型负责改写，Grok 只是目标视频模型。有图统一标为 `reference-image` / `reference`，无图不附带帧角色；不能把第二张图称为尾帧。数量无效时不声称素材可执行，无效时长、分辨率或尺寸不作为可执行条件；只读 `generationIssues` 不得进入提示词正文或诱导补造参数。

Grok 的 frameSize 使用实际 aspect_ratio，清晰度使用 resolution，不宣称请求了固定像素宽高。Grok 不传声音控制，因此 `audioEnabled` 缺省而非 `false`；保留用户声音创作要求，但不承诺渠道支持音频控制或保证静音。本地身份仍比较型号、渠道、协议、地址、脚本及实际尺寸/时长/分辨率原始输入；仅旧模式、声音、水印变化不使 Grok 结果失效。其他模型及脚本保持原比较规则。

保留原图分析默认关闭、参考顺序、token 首次出现顺序、上游只读、取消与迟到响应保护、继续优化失败保留完整稿和确认仅回填。
