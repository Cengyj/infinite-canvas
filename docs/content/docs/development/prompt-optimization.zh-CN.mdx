# 提示词优化设计

提示词优化在图片工作台、视频工作台、画布图片/视频节点及对应生成配置的组装提示词中提供统一入口。用户选择文本模型，调整来源草稿和补充要求，查看流式结果，确认后才替换当前提示词；应用结果不会直接发起图片或视频生成。

工作台提示词操作沿用旧版工作台布局：小号「提示词」标签旁设置同高等宽的三列描边按钮，顺序为「提示词库」「查看资产」「优化提示词」。三列网格使用紧凑 12px 文案和小间距，适配桌面固定 420px 栏；宽度低于 390px 时隐藏图标，保留按钮文字。

画布图片/视频节点沿用旧版入口布局：32px 魔棒图标按钮位于普通提示词面板底部工具栏「提示词库」之后、模型选择之前，不另占一行。放大编辑窗口在标题右侧提供图标加文字入口，待编辑窗口关闭动画结束后打开优化弹窗。两处入口均允许空稿打开；配置组装器保持现有入口。

本轮源码审阅确认，图片/视频提示词优化及模型预设在回退前备份中已经存在，相关入口和预设比对一致。当前改动针对已有功能中的上下文缺失、图片引用编号、编辑交互与配置持久化问题，不新增一套优化链路。

## 官方依据与模型边界

已实际获取的 [GPT-6.1 Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)确认精确模型 `gpt-6.1-sol` 支持文字、图片输入和文字输出；[推理指南](https://developers.openai.com/api/docs/guides/reasoning)包含该模型的 Responses API 示例，并说明推理强度支持 `low`、`medium`（默认）、`high`、`xhigh`、`max`，不支持 `none` 或 `minimal`。[Responses 请求参考](https://developers.openai.com/api/reference/resources/responses/methods/create)的 `reasoning.effort` 不包含 `auto`；界面“自动”表示省略该参数，让模型使用默认值，显式配置才发送对应值。`reasoning.context` 或 `reasoning.summary` 中的 `auto` 不是推理强度。

[图像输入指南](https://developers.openai.com/api/docs/guides/images-vision)与请求参考规定 Responses 使用 `input_text` 和 `input_image` 内容块，后者的 `image_url` 为完整图片 URL 或 base64 data URL，也可使用 `file_id`。项目内部消息格式需要在请求层转换，不能直接作为 Responses 内容块发送。

精确模型页链接的 [GPT-6 指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra#gpt-61-sol)把“Prompting best practices”列为可供家族模型评估的起点，并明确其中行为观察来自 Astra，需用所选模型和实际任务验证。本项目采用明确输出格式、清楚表达约束优先级和减少套话等设计原则，不把这些建议写成 Sol 已验证的效果。官方能力说明也不证明当前兼容渠道、代理或账号可用，实际改写质量仍待人工验收。

| `lib/image-generation-size.ts` | 从图片 API 原样抽取的请求尺寸解析；Gemini 生成与优化共用实际比例/分辨率规则 |

| `lib/canvas/canvas-resource-references.ts` | 普通节点的 @ 资源列表与图片编号，复用实际生成输入顺序 |
| `lib/canvas/canvas-prompt-optimization.ts` | 将当前节点、连线、组和再生成方式转换为优化输入 |
| `hooks/use-prompt-optimizer.tsx` | 从编辑器创建会话、发现来源变化、应用前复核并回填 |
| `components/prompt-optimize-dialog.tsx` | 来源和结果编辑、模型选择、流式预览、停止、复制及继续优化 |
| `services/api/prompt-optimization.ts` | 组织优化指令与只读上下文，读取可选参考图，验证输出 |
| `services/api/image.ts` | 复用 OpenAI / Gemini / 自定义文本脚本通道，并为优化校验完整结果 |

入口提供 `getInput` 和 `onApply`。打开时读取输入快照，弹窗中的修改只影响本次优化请求；点击应用时重新读取当前输入并比较，成功后调用编辑器原有更新动作。全局渠道和文本模型直接读取现有配置 store，不从页面逐层传递。

允许来源为空时打开弹窗，打开本身不发送请求。用户可以在弹窗内填写初始草稿，只有开始优化请求前才要求来源非空；取消仍不改动原编辑器。

优化会话和结果只保存在当前组件内存中。关闭后不会新增独立历史或持久化结构；应用后的提示词仍按所在工作台或画布原有规则保存。API Key 保存在浏览器本地，请求沿用现有直连或显式开启的本地代理。内置 OpenAI 文本请求发送 `store: false`；自定义脚本的请求行为由脚本负责。

## 上下文与引用规则

- **草稿与上游正文分开**：原始可编辑提示词作为 `prompt`，连线文本作为只读 `upstreamText`。优化指令要求理解上游正文但不复制到结果，避免下次生成重复追加 `【文本N】`。
- **生成模型与优化模型分开**：`generationModel` 描述目标图片/视频模型及其 OpenAI、Gemini 或脚本通道，`textModel` 才负责本次改写。优化不切换生成模型，也不把模型名称或参数机械写进提示词。
- **生成系统指令**：图片场景通过只读 `generationSystemPrompt` 提供实际生成配置的 `systemPrompt`。优化遵循其中的生成约束，但不把它复制回草稿，也不把它当成改变优化输出合同的指令；字段参与快照比较，修改后旧结果失效。
- **Gemini 图片尺寸**：内置图片请求与优化上下文共用 `resolveGeminiImageConfig`，分别以实际 `aspectRatio` 和 `imageSize` 填写 `frameSize`、`resolution`，避免把原始像素尺寸或用户输入比例当作服务端最终参数。原有尺寸解析和限制原样抽取，不新增边界；尺寸编辑尚未有效时省略未解析字段，生成时仍由原请求校验。保存的自定义脚本保持自身输入约定。
- **实际视频参数**：生成与优化共享 resolveVideoGenerationConfig。非 Grok 与保存脚本保留原模式、时长规则，不推测脚本内部。内置 Grok 按当前渠道文档与成功请求发送六字段 model/prompt/seconds/aspect_ratio/resolution/reference_images，frameSize 使用实际 aspect_ratio，quality 使用 resolution，不把界面像素尺寸误称为请求输出宽高。0 图文生、1–7 图普通参考，旧模式不参与；共享规则已按确认放开 1.5 无图/单图 1080p，2–7 图仍限 480/720p，经典时长与清晰度规则不变。多图无效 1080p 属于 resolution 问题，不推断首帧、不自动降级。有效 1–3 秒不夹成 4 秒；有图统一 reference-image/reference，无图无帧角色。无效数量、时长、分辨率、尺寸不作为可执行条件；generationIssues 只读，不得进入正文或诱导补造设置。Grok 的 audioEnabled 缺省，不能理解为 false、音频控制或保证静音；被拒绝音视频附件不列为可用参考。Gemini 只描述实际首份音视频，图片规则保持独立。
- **Grok 渠道证据与本地策略分开**：yuanai.uk 关键边界采样已完成无图、单图、7 图、短时长与时长上界，并明确拒绝经典不支持的清晰度/时长、1.5 多图 1080p、8 图和 16 秒。四例真实项目服务调用另以无 mock 网络完成经典/1.5 的 7 图、1 秒、480/720p。历史余额阻断已解除；本轮不是全部组合穷举或质量通过。用户随后确认“按实测放开”，本地现已实现 1.5 无图/单普通参考图 1080p，2–7 图仍禁用该档；此前渠道结果不是本次新增付费生成，也不是本次行为回归结果；没有测试首帧模式，完整浏览器入口仍待验收。详见[Grok 方案与证据](/zh-CN/docs/progress/grok-video-frontend-plan)。
- **图片意图与角色**：`imageIntent` 区分 `create`、`reference`、`edit`；只有自身原图确实进入实际参考列表，才按源图编辑构造上下文，不能因为节点已有图片或存在普通参考图就认定为编辑。`imageRoles` 按实际顺序标为 `source-image`、`reference-image`、`first-frame` 或 `last-frame`，保留在内部上下文及快照比较中；请求只在 `referenceImages[].role` 和实际图片前的标签中附带角色，不在 `generationContext` 重复发送。技术角色不等于用户未指定的风格、构图等创作用途。
- **普通节点**：`@` 菜单、“图片N”标签和优化参考列表均按实际生成顺序编号。新建结果时，自身原图有内容才排在首位；原地重新生成不自动加入自身旧图，但自身若通过组或其它连线被明确引用，仍保留其实际位置。编号复用生成输入解析，包括组展开、去重和连接配置节点的输入优先级，不修改草稿中已有文字。
- **配置节点**：非空组装草稿按 `@[node:id]` 选择输入；组 token 展开有效子资源，并按节点 ID 去重。没有组装内容时，现有隐式输入只在优化快照中转换为 token 草稿，用户应用前不写回节点。
- **token 不变**：结果必须保留全部不同 token 及其首次出现顺序，可以重复引用，不能新增、删除、替换 ID 或用显示标签代替。顺序决定真实生成时的参考编号。弹窗用可读 chip 展示 token；选区复制和剪切输出原始 `@[node:...]`，不把可读标签写入剪贴板，只读结果不会因剪切被删除。
- **参考图分析默认关闭**：关闭时只发送引用标签、名称和角色，不从文件名推测画面；开启后按实际顺序读取原图，连同标签和角色发送给文本模型。视频、音频只提供名称说明，不发送其媒体供视觉或听觉分析。
- **本地生成身份**：generationIdentity 仅在本地比较型号、渠道、协议、地址、脚本和原始 config.size，视频再比较原始 videoSeconds、vquality。Grok 不比较无效控制项 videoMode/videoGenerateAudio/videoWatermark，仅它们变化不使结果失效；其他视频模型和脚本继续比较三项。实际相关原始值即使都无效、被省略或换算相同，变化仍使结果失效；身份不发送给优化模型，无效条件不成为可执行设置。

## 改写约定与文本请求

服务先应用共同约定，再按图片或视频加入场景规则。共同约定保留原语言、主体身份与数量、明确排除项、可见文字及其引号、标点和指定换行；采纳新增补充要求，仅在明确冲突处覆盖原创作细节，不覆盖 token 合同。来源和上游内容作为创作资料，不能反过来改写输出约定。图片规则区分新建、参考创作与源图编辑，明确要改什么和保留什么；视频规则区分首尾帧与全能参考，保持主体、动作、时间和空间连续，短片只安排可完成的动作，声音遵从显式要求及实际开关。

模型应只返回可直接使用的提示词正文，不增加解释、标题、JSON、代码围栏或额外包裹引号。程序仅处理首尾空白，不用猜测式清洗剥除引号或围栏，避免破坏用户要求画面展示的文字；输出是否遵守正文格式属于人工验收项。参数只约束构图、节奏和输出条件，不机械填满摄影术语，也不凭文件名或未分析媒体猜测角色。

新载入的 OpenAI / Gemini 默认文本脚本模板修复图文内容转换、请求路径与完整终态及拒绝校验；不会自动覆盖用户已保存的脚本。保存脚本仍由用户控制，不能假定旧脚本已获得模板修复。原生 Gemini 文本请求过滤标记为 `thought` 的内容，只把回答正文交给优化结果。

## 回填、失效与取消

只有完整、非空且 token 合法的结果可以应用。OpenAI / Gemini 的内置请求必须返回合法完整终态，截断、拒绝、上游错误和断流不成为可应用结果；自定义文本脚本必须正常结束并返回文本。

会话绑定当前工作台会话或画布项目/节点。来源草稿、参考图顺序、名称或内容、上游文本、生成系统指令、原始图片尺寸或有效比例/分辨率、引用映射或生成上下文变化后，旧快照不可回填，用户可重新读取当前输入。弹窗按实际解析到的文本渠道检查模型配置变化，并在迟到响应完成时再次核对最新模型和来源快照；不能只比较全局默认渠道。模型失效时要求重新配置，不静默切换渠道。

修改补充要求后，已有完整结果不能直接应用，但仍可作为“继续优化”的基础，与新要求一起请求；失败或停止时保留旧完整稿供查看和后续修改，不把它重新标为符合新要求的可应用结果。修改来源、参考图分析开关或文本模型配置同样需要重新优化。

停止、关闭、编辑器卸载、来源失效或文本模型配置变化会取消当前请求；取消后的迟到片段不会更新预览。停止或失败时保留之前完整结果，不把半段预览应用到页面。普通节点回填复用 `updatePrompt`，同时维护局部输入与节点元数据；配置节点回填原始 token 草稿。应用后不保留影响下一次生成的额外 binding。

优化弹窗内的键盘事件与画布快捷键隔离，避免编辑文字时同时触发画布删除、撤销或全选；Escape 仍使用现有弹窗关闭行为。复制/剪切按选区序列化原始 token，粘贴只接收纯文本，仍需通过完整结果与引用校验才能应用。

## 人工验收案例

以下 21 例是输入和判断标准的示意，均未经过真实模型验证，也不是预设的模型输出。先检查优化后的文字，再在用户自行安排的生成验收中确认画面或声音；界面和异常路径可用模拟响应验证，不能据此宣称真实模型质量通过。


| 输入条件（示意） | 必保留项 | 判断标准 |
| --- | --- | --- |
| 1．中文包装：包装正面两行文字为 `“早安·麦香”`、`净含量：250 g`，要求优化商品图提示词。 | 中文、引号、中点、冒号、空格、数值和两行布局。 | 两行逐字不变，不改成英文、不编品牌；不因去引号清洗损坏文案。 |
| 2．仅背景：源图为红色水杯，要求“只换成浅蓝背景，杯子不变”。 | 杯子身份、数量、颜色、形状和未要求修改的细节。 | 只有实际传入源图才标 `source-image` / `edit`；文字明确背景变化，未重新设计杯子。 |
| 3．透明背景：无参考图，要求单个布偶猫贴纸，配置透明背景。 | 一只猫、贴纸用途、透明背景。 | 不添加地板、风景、纯色背景或棋盘格；不把透明理解为画出透明网格。 |
| 4．多参考图：图片1负责产品外形，图片2仅负责配色，分析开关分别关/开。 | 编号、顺序、用户指定职责，未指定职责保持未指定。 | 关闭时不声称看过画面；开启时只用必要观察，不把图片2擅自变为构图或源图。 |
| 5．视频单首帧：在明确支持首帧的非内置 Grok 路径选择 frames 一图，要求角色缓慢左转；另测 Grok 同图。 | 身份、数量、方向及真实输入语义。 | 前者标 first-frame；内置 Grok 仅标 reference-image，不凭数量或文件名虚构帧角色和新主体。 |
| 6．视频首尾帧：使用明确支持首尾帧的其他模型/脚本，图1门关闭、图2门打开，要求固定镜头；另测 Grok 同图。 | 同一扇门、用户指定顺序和固定镜头。 | 前者按真实 first-frame/last-frame 连续连接；Grok 两图只是普通参考，不能声称渠道收到独立起止帧或交换用户指定顺序。 |
| 7．视频多参考：三图分别指定人物、服装、场景职责，覆盖 Grok 与其他模型/脚本。 | 职责、编号、顺序和实际选材。 | Grok 不读取旧模式，1–7 图均为普通参考；其他路径保留原模式解析，不把三图写成首中尾帧；Gemini 音视频名称仅描述实际首项。 |
| 8．短动作：4 秒视频，要求“小球滚动后停下”，镜头静止。 | 单球、滚动到停止、静止镜头、短时长。 | 不增加多场景或新剧情；其他模型的 `videoSeconds=-1` 上下文仍为 4 秒，内置 Grok 则报告无效并省略时长；Grok 1/3 秒必须与实际提交一致，不宣称自动时长。 |
| 9．声音：有真实音频开关的路径分别要求仅雨声/无声雨景；Grok 也输入这些创作要求。 | 声音或静音要求、排除音乐和人声、固定镜头。 | 有开关时遵循实际 audioEnabled；Grok 缺省该字段，保留要求但不承诺音频控制或保证静音，均不虚构音频分析。 |
| 10．画布 token：草稿含 `@[node:group-a]`、`@[node:image-b]`，组内也包含 image-b；另测空组装草稿。 | 原始 ID、首次出现顺序、组资源去重、隐式输入。 | 不把 token 换成标签或展开正文；空稿只在优化快照中补 token，确认应用前不写回节点。 |
| 11．上游正文：连接文字“主角戴圆框眼镜”，当前草稿“站在窗边”。 | 当前可编辑草稿与只读 upstreamText 的职责。 | 理解上游限制但不把整段正文再次复制进草稿；实际生成只追加一次上游内容。 |
