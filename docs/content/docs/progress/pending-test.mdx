# Pending Tests

The current release needs manual verification in these areas:

- Image and Video Studio prompt optimization: both workbenches should keep the prompt title and the “Prompts,” “Assets,” and “Optimize” actions on one row that fills the editor width. Narrow screens may tighten typography and padding or hide decorative icons, but labels must remain visible. Optimize should remain openable with an empty prompt. The image scenario should focus on subjects, composition, materials, lighting, exact visible text, and spatial relationships, without inventing a background for transparent output. The video scenario should distinguish text-to-video from image-to-video and use the current duration, normalized to 1–20 seconds, frame size, and audio setting to build a realistic opening, progression, ending, subject motion, horizontal or vertical movement, camera movement, pacing, and continuity; it should default to a continuous shot and must not return a static-only description or invent dialogue, music, or sound effects merely because audio output is enabled. Completed output should be editable, copyable, and reusable for another optimization pass. Additional requirements should remain after success and continue to affect re-optimization. Results should only write back after confirmation without starting generation.
- Canvas image and video prompt optimization: only built-in Image and Video nodes should show the transparent, flat Optimize action in the lower prompt panel and expanded editor. It should open for an empty prompt and be disabled while that node is generating; Config Composer and plugin nodes should not expose it because their structured references or custom semantics must remain untouched. The dialog should follow the active canvas theme with low visual weight, and provider settings must open above it. An Image node with content should analyze only its current primary image, while an empty Image node or any Video node should use the same ordered connected references as final generation. Opening the dialog must not read image data until the user enables reference analysis. Applying should only update the current node prompt and must not start generation. Replacing the primary image, adding, removing, or reordering references, or changing image size/transparency or video duration/frame/audio settings should stop the first generation attempt and require confirmation before the next attempt proceeds. Switching nodes, deleting a node, clearing the canvas, or changing projects must prevent stale optimization sessions or bindings from applying elsewhere.
- Prompt optimization reference images and request boundaries: the dialog should show an immutable reference snapshot labeled in stable order as “Image 1,” “Image 2,” and so on. Visual analysis defaults off; while off, only labels, count, whether final generation has references, and generation context are sent to the text model. The request must distinguish references used by final generation from image content attached for this optimization. The provider model editor should no longer expose an image-input capability switch; any text model may read, compress, and receive images after the user enables analysis and while no more than four references are present. Each prepared image must remain at or below 3MB and the combined payload at or below 12MB; read or payload failures must be explicit and must never silently drop an image or shift numbering, and stopping optimization must also cancel in-progress image reads. The optimizer must not infer that the first or last image is a first frame, last frame, style reference, or any other role unless the prompt says so. If references are added, removed, or reordered after an optimized result is applied, the first generation attempt must stop and ask the user to verify labels. Changes to the optimized frame size, transparent-background setting, video duration, or audio setting should also require confirmation before a second attempt proceeds. The shared video request must fail clearly above seven references instead of uploading only a subset; concurrent upload, paste, and asset insertion must also stay within seven, report the actual accepted count, and retain successful siblings when one image fails. Starting a new session, loading history, or leaving the page during upload must not append stale images or leak new files, and damaged images must never enter local file storage. Cleanup caused by assets, canvas content, or current-reference removal must preserve images owned by an upload batch, the active workbench, or an in-flight generation snapshot until its log is committed. OpenAI-format optimization should use Responses `input_text` / `input_image` with `store: false`; Gemini should use `systemInstruction` and `parts.text` / `inlineData`. Custom text scripts should receive both the original multimodal `messages` and a separate `images` array. Reference-image Data URLs must not be written to optimization history, persistent configuration, or logs.
- Prompt optimization state and errors: optimization should use and remember the selected text model. Changing the source, model, or reference-analysis setting should invalidate the old result; changing or clearing additional requirements should mark it stale, while manually editing a complete result should make that result applicable again. Partial, truncated, refused, or empty output must never be copyable or applicable. Stopping, closing, reopening quickly, switching models, starting a workbench generation, or receiving a new Agent prompt must not let an old request overwrite current content. Incomplete text-model credentials should open provider settings above the optimization dialog while preserving the draft and without leaving an empty model menu over settings. Both formal requests and bundled custom text templates must reject incomplete or refused terminal states, remote reference-image HTTP errors or non-image responses must not be submitted as images, and bundled video templates must not silently ignore unsupported references. Ordinary relative paths should default to `/v1`, while explicit `/v1` or `/v1beta` paths must preserve that version without duplication. When an OpenAI video job completes without an intermediary download URL, the template should fetch `/videos/{id}/content` with authentication. Gemini video should download a Blob with the `x-goog-api-key` header, and its final asset URL, history, and logs must never contain the API key. Malformed streams, upstream termination, script authentication/rate-limit/CORS failures, and denied clipboard writes must report their actual outcome rather than success.
- OpenAI-format multi-reference image editing: a single reference should use `image`, while multiple references should use the official `image[]` multipart field. Generic requests must send neither the old `response_format` parameter nor the GPT-Image-only `output_format`; GPT Image should use its default PNG base64 response, DALL·E its default URL response, and both should parse correctly. A generation request must not exceed the official 10-image limit, and built-in edit requests should fail clearly before sending more than 16 references. The bundled OpenAI image script template should follow the same rules.
- GitHub Container Registry: pushing a version tag should publish pullable `linux/amd64` version and `latest` images to `ghcr.io/cengyj/infinite-canvas` and `ghcr.io/cengyj/infinite-canvas-docs`; Docker Compose and documentation examples should reference the same namespace.
- Gemini native image parameters: verify both text-to-image and unmasked reference-image generation; `generationConfig` should retain `responseModalities`, pass parameters only through `imageConfig`, and never include `responseFormat.image`. Recognized Gemini image models should submit aspect ratio and output size according to their capabilities: Flash Lite should allow only 1K, Pro should reject 512, and unsupported sizes should fail clearly before a request is sent; Gemini 2.5 and unknown models should not receive `imageSize`. The 3.1 Flash family should accept its supported 1:4, 1:8, 4:1, and 8:1 ratios without being blocked by the general 3:1 validation; custom model scripts and other channel protocols should remain unchanged.
- Default model providers: in a fresh browser profile, Settings should show `OpenAI` followed by `Google`, both using `https://direct.foropencode.com`. OpenAI should expose its four preset models with `gpt-5.6-sol` as the text model and default text selection; Google should use the Gemini protocol and expose only `gemini-2.5-flash-image-preview`, `gemini-3-pro-image-preview`, and `gemini-3.1-flash-image-preview`, all as image models. Each Preview name should remain unchanged in requests while using its corresponding Gemini image capability profile. Adding or switching a provider to the Gemini protocol should still default to `https://generativelanguage.googleapis.com`, and existing persisted providers—including an existing `gpt-5.5` selection—should remain unchanged.
- Settings persistence and import: verify that a fresh profile, an existing version-0 settings store, an old flat settings object without `channels`, and a customized single-provider setup all hydrate correctly without restoring a provider the user deleted. Adding, editing, or deleting a provider should persist one complete normalized settings snapshot. Exporting and importing settings should preserve providers, selected models, WebDAV settings, prompt sources, and built-in prompt-source defaults; malformed version-1 JSON should be rejected without leaving a partially normalized configuration. URL `baseUrl` / `apiKey` import should update the first provider once and remove credentials from the address bar.
- Canvas navigation: the canvas should open in Move mode by default, and the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should drag elements directly and pan only when dragging the blank background. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning from any position and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability: importing an image should open its prompt panel, resizing it immediately from any corner should temporarily hide the panel, remain smooth without flashing or triggering a maximum update depth error, and restore the panel after release. Prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration should continue to work.
- Text output count: both a text node's lower prompt panel and a generation configuration node in Text mode should expose an independent generation count from 1 to 15, default to one, and create that many text nodes. Changing the text count must not alter the image count, and switching a generation configuration node back to Image should continue to use the configured image count.
- Node editing entry points: the image toolbar should default to icons without labels and no longer include Edit; the text toolbar should no longer include Edit or Edit text. Clicking an image, text, or video node without dragging should open its lower prompt panel directly, while image toolbar labels can still be enabled explicitly from the toolbar settings.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; only clicking the count control should expand or collapse the slots upward and to the right, while double-clicking the image should open its large preview. Every completed secondary image should keep a clearly legible primary-image action visible in both themes. Expanded groups should remain expanded when clicking elsewhere, dragging, resizing, or previewing, and multiple groups may remain expanded together.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.
- Multi-image resize: resizing the root node while child images are expanded should keep the group expanded and resize normally without triggering nested React updates or an application error.
- Multi-image alternatives: expanded images should use up to four columns so larger batches stay compact; double-clicking any completed child image should preview that exact image without changing the primary image. Every completed image, including the primary image, should provide an independent download action, while alternatives should also keep clearly legible create-copy and set-primary actions in both themes. Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Local media persistence safety: automatic image, video, and audio cleanup must preserve another tab's active data and skip deletion when tab coordination is unavailable; a failed IndexedDB restore must never trigger cleanup from an empty fallback state. Canceling, replacing, or racing image selections in the asset editor must reclaim only uncommitted drafts, while replacing a saved image or changing it to text should safely reclaim the old unreferenced file. ZIP and WebDAV asset/canvas imports must keep written files leased until metadata is committed, and Undo/Redo history images must remain available until their snapshots are discarded.
- Settings import/export and WebDAV-related configuration.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.

The Chinese version contains the complete item-by-item acceptance checklist.
